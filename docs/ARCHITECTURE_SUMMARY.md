### 1.2 数据流

```
1. 用户上传 PDF
   └─→ PDFProcessor 解析 → ChromaDB 向量化存储
   
2. 用户发送消息
   └─→ llm_chat_service.chat()
       └─→ 构建 System Prompt (含 PDF_SESSION_ID + 文档预览)
       └─→ qwen_agent_service_v2.chat_completion()
           └─→ 更新 Assistant.system_message
           └─→ Qwen-Agent bot.run()
               └─→ 自动解析工具调用
               └─→ 执行 LCA 工具 (qwen_agent_tools.py)
                   └─→ tool_service 执行实际操作
                       └─→ 搜索文档 / 记录数据到 MongoDB
               └─→ 循环直到任务完成
           └─→ 返回结果
       └─→ 返回给前端
```

## 2. 先前工作的价值

### 2.1 工具构建 ✅ 核心价值

| 工具 | 作用 | 当前状态 |
|------|------|----------|
| `search_document` | 文档语义搜索 | ✅ 正常使用 |
| `define_lca_scope` | 定义功能单位 | ✅ 正常使用 |
| `record_process_flow` | 记录 LCI 流 | ✅ 正常使用 |
| `record_parameter` | 记录中间参数 | ✅ 正常使用 |
| `execute_calculation` | 执行计算 | ✅ 正常使用 |
| `get_session_summary` | 获取摘要 | ✅ 正常使用 |

**这些工具是系统的核心功能**，Qwen-Agent 框架只是调用它们的"调度器"。

### 2.2 LoRA 微调 ✅ 显著提升

LoRA 适配器 (`lca_lora`) 的作用：
- **领域知识**: 理解 LCA 术语（功能单位、LCI 流、影响类别等）
- **工具调用格式**: 更准确地生成工具调用参数
- **推理模式**: 学习专家级的数据提取流程

**对比测试**：
```bash
# 使用 LoRA 模型
./restart_services.sh

# 使用基座模型（对比）
USE_BASE=1 ./restart_services.sh
```

### 2.3 System Prompt ✅ 行为指导

System Prompt 定义了：
- LCI 数据类别（11 种）
- 工作流程（Anchor → Inputs → Outputs → Validation）
- 工具使用指南
- 自动 Session ID 注入

### 2.4 双层知识库架构 ✅ 数据隔离

| 知识库 | 用途 | 存储 |
|--------|------|------|
| 临时知识库 | 用户上传的 PDF | ChromaDB (会话级) |
| 永久知识库 | ecoinvent 数据 | MongoDB (全局) |

### 3.3 用户操作流程（预期）

1. **上传文档** → 系统自动提取 LCI 数据
2. **确认数据** → 用户检查提取的数据是否正确
3. **匹配 ecoinvent** → 系统自动匹配，用户确认
4. **生成模型** → 系统生成 pyLCA 代码
5. **执行计算** → 连接 openLCA 执行 LCIA
6. **查看结果** → 显示环境影响评估结果

## 4. 服务管理

### 4.1 启动服务

```bash
# 1. 启动 vLLM (GPU 推理引擎)
./start_vllm.sh

# 2. 启动后端和前端
./restart_services.sh

# 使用基座模型（对比测试）
USE_BASE=1 ./restart_services.sh
```

### 4.2 停止服务

```bash
# 停止后端和前端（保留 vLLM）
./stop_services.sh

# 停止所有服务（包括 vLLM）
./stop_services.sh --all
```

### 4.3 查看日志

```bash
tail -f /tmp/backend.log   # 后端日志
tail -f /tmp/frontend.log  # 前端日志
tail -f /tmp/vllm.log      # vLLM 日志
```

## 5. 关键配置

### 5.1 模型参数

| 参数 | 值 | 说明 |
|------|-----|------|
| `max_model_len` | 16384 | vLLM 上下文长度 |
| `max_tokens` | 4096 | 输出最大 token 数 |
| `temperature` | 0.6 | Qwen3 推荐值，适合数据提取 |
| `gpu_memory_utilization` | 0.85 | GPU 显存使用率 |

### 5.2 环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `LLM_SERVICE` | `qwen_agent` | LLM 服务类型 |
| `VLLM_MODEL_NAME` | `lca_lora` | 模型名称 |
| `VLLM_API_BASE` | `http://localhost:8080/v1` | vLLM API 地址 |

## 6. 总结

### 先前工作的价值

| 工作 | 价值 | 当前使用情况 |
|------|------|--------------|
| **LCA 工具集** | ⭐⭐⭐⭐⭐ | 核心功能，每次对话都在使用 |
| **LoRA 微调** | ⭐⭐⭐⭐ | 提升领域理解和工具调用准确性 |
| **System Prompt** | ⭐⭐⭐⭐ | 指导模型行为和工作流程 |
| **双层知识库** | ⭐⭐⭐⭐ | 数据隔离，支持语义搜索 |
| **PDF 处理管道** | ⭐⭐⭐⭐ | 文档解析和向量化 |
| **MongoDB 数据模型** | ⭐⭐⭐⭐ | 数据持久化，支持未来扩展 |

**结论**：先前的工作**非常有意义**，它们构成了系统的核心功能。Qwen-Agent 框架只是一个"调度器"，真正的价值在于你构建的工具、微调的模型和设计的数据流。
