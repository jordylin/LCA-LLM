# EcoLLM 训练数据构建路线图

**更新日期**: 2025-11-20  
**策略**: 迭代式混合微调 + 评估驱动

---

## 🎯 核心策略

### 混合训练原则

```
每个阶段都包含：
- 全流程提取（Full Process）: 65-75%
- 短对话问答（Short QA）: 25-30%
- 元认知数据（Meta）: 5%

难度混合：
- 每个阶段都包含 Simple/Medium/Complex
- 但权重逐步向Complex倾斜
```

### 评估驱动

```
每个阶段完成后：
1. 训练模型
2. 在测试集上评估
3. 分析错误类型
4. 决定是否进入下一阶段
```

---

## 📋 三阶段路线图

### 阶段1: 快速验证（MVP）

**目标**: 验证工具链和基本能力

**数据量**: 300样本

**数据构成**:
```
全流程提取: 200样本
├─ Simple: 100样本 (50%)
├─ Medium: 60样本 (30%)
└─ Complex: 40样本 (20%)

短对话QA: 80样本
├─ 简单查询: 40样本（"What is the powder consumption?"）
├─ 中等查询: 30样本（"Calculate energy per kg"）
└─ 复杂查询: 10样本（"Compare process vs post-processing energy"）

元认知数据: 20样本
└─ 身份认知、能力边界、错误处理
```

**文档类型分布**:
```
Tier 1（短文档）: 40%
├─ Batch Production Record
├─ Build Job Log
└─ Material Traceability

Tier 2（中文档）: 35%
├─ Technical Process Report
└─ Environmental Assessment

Tier 3（长文档）: 25%
└─ Research Case Study
```

**通过标准**:
- ✅ 工具调用格式正确率 > 90%
- ✅ Simple场景能完成基本提取
- ✅ 无严重JSON格式错误
- ✅ 能正确使用batch search

**如果不通过**:
- 修改System Prompt
- 优化工具定义
- 检查数据格式
- **不要扩展数据量**

**时间预估**: 1-2周

---

### 阶段2: 能力扩展

**目标**: 建立稳定的LCI提取能力

**数据量**: 900样本（累积）

**新增数据**: 600样本

**数据构成**:
```
全流程提取: 400样本
├─ Simple: 100样本 (25%)
├─ Medium: 150样本 (37.5%)
└─ Complex: 150样本 (37.5%)

短对话QA: 150样本
├─ 简单查询: 50样本
├─ 中等查询: 60样本
└─ 复杂查询: 40样本（增加计算类、对比类）

元认知数据: 50样本
└─ 增加边界情况处理
```

**累积训练**:
```
阶段1数据: 300样本（全部保留）
阶段2新数据: 600样本
总计: 900样本
```

**文档类型分布**:
```
Tier 1: 30%
Tier 2: 40%
Tier 3: 30%（增加长文档占比）
```

**通过标准**:
- ✅ Simple场景准确率 > 75%
- ✅ Medium场景准确率 > 65%
- ✅ Complex场景准确率 > 55%
- ✅ 能正确区分10个LCI类别
- ✅ Energy拆分准确率 > 70%

**如果不通过**:
- 分析错误类型（搜索失败？分类错误？计算错误？）
- 针对性增加弱项数据
- 优化Batch Search关键词
- 可能需要简化Complex场景

**时间预估**: 2-3周

---

### 阶段3: 鲁棒性提升

**目标**: 达到生产就绪水平

**数据量**: 1600样本（累积）

**新增数据**: 700样本

**数据构成**:
```
全流程提取: 500样本
├─ Simple: 50样本 (10%)
├─ Medium: 150样本 (30%)
└─ Complex: 300样本 (60%) ← 重点

短对话QA: 150样本
└─ 边界情况、异常处理

元认知数据: 50样本
```

**累积训练**:
```
阶段1-2数据: 700样本（采样80%，保持平衡）
阶段3新数据: 700样本
总计: 1400-1600样本
```

**Hard Negatives重点**:
```
1. 缺失数据场景（只有部分LCI类别）
2. 单位不一致（需要转换）
3. 多工艺对比文献（需要识别主工艺）
4. 干扰数据（对比数据、历史数据）
5. 复杂计算（多步骤、多参数）
6. 非标准表达（异常术语、缩写）
```

**通过标准**:
- ✅ Simple场景准确率 > 80%
- ✅ Medium场景准确率 > 75%
- ✅ Complex场景准确率 > 65%
- ✅ **真实文献测试集 F1 > 70%**（关键）
- ✅ 能处理不完整数据（不幻觉）

**时间预估**: 3-4周

## 🔧 短对话QA数据生成

### 自动生成策略

从每个全流程标注session自动生成QA对：

```python
# 为每个记录的Flow生成1-2个问题

Flow: Ti-6Al-4V powder, 20.83 kg
→ Q1: "What is the Ti-6Al-4V powder consumption?"
→ Q2: "How much raw material was used?"

Flow: Process Energy, 147.26 kWh
→ Q1: "What is the process energy consumption?"
→ Q2: "Calculate the energy per kg of product."

Flow: Product, 17.36 kg
→ Q1: "What is the product output?"
→ Q2: "What is the functional unit?"
```

### 问题类型分布

```
简单查询（50%）:
- "What is the [category] consumption?"
- "How much [material] was used?"

中等查询（30%）:
- "Calculate [flow] per kg of product."
- "What is the normalized [category]?"

复杂查询（20%）:
- "Compare [flow_a] and [flow_b]."
- "What percentage of total energy is [specific_energy]?"
- "Based on the parameters, calculate [flow]."
```

## ⚠️ 风险预案

### 阶段1失败

**现象**: 工具调用格式错误率 > 20%

**原因分析**:
- System Prompt不清晰
- 工具定义有歧义
- 训练数据格式错误

**应对**:
- 修改Prompt
- 简化工具定义
- 检查JSONL格式
- **不要扩展数据量**

---

### 阶段2效果不佳

**现象**: Medium场景准确率 < 60%

**原因分析**:
- 搜索策略不佳
- 类别分类混淆
- Energy拆分不清

**应对**:
- 增加Batch Search示例
- 增加类别分类训练样本
- 优化Energy分类说明
- 可能需要增加到1200样本

---

### Complex场景始终不佳

**现象**: Complex场景准确率 < 50%

**原因分析**:
- 计算推理能力不足
- 参数识别困难
- 任务过于复杂

**应对**:
- 简化Complex场景（降低难度）
- 增加中间步骤提示
- 考虑使用更大的base模型
- 或者暂时放弃Complex，专注Simple/Medium

---

## 📝 总结

### 核心原则

1. **混合训练** > 分阶段训练
2. **评估驱动** > 盲目扩展
3. **真实文献** > 生成文档（逐步提升占比）
4. **快速验证** > 完美规划

### 一句话

**"300样本快速验证 → 900样本能力扩展 → 1600样本鲁棒性提升，每个阶段都混合难度和任务类型，评估通过才进入下一阶段。"**
